Документація
1. Опис проєкту

Проєкт являє собою простий HTTP-сервер на Python для завантаження та зберігання зображень.

Основна функціональність:

обробка HTTP-запитів GET та POST;
відображення головної сторінки;
завантаження зображень;
перевірка формату файлу;
перевірка розміру файлу;
генерація унікального імені для кожного завантаженого зображення;
збереження зображень у папці images/;
повернення посилання на завантажене зображення;
логування успішних та помилкових операцій;
запуск проєкту як локально, так і за допомогою Docker Compose;
використання Nginx як проксі-сервера.

2. Структура проєкту
project/
├── app.py                  # Основний Python-бекенд
├── requirements.txt        # Залежності Python
├── Dockerfile              # Dockerfile для Python-бекенду
├── compose.yml      # Конфігурація Docker Compose
├── nginx.conf              # Конфігурація Nginx
├── images/                 # Завантажені зображення
├── logs/                   # Файли логів
└── static/                 # Статичні файли (HTML, CSS, JS)


Опис основних файлів та директорій

app.py
Основний файл Python-застосунку.
У ньому реалізовано HTTP-сервер та обробники:
GET /;
POST /upload;
обробка помилок;
перевірка завантажених файлів;
збереження зображень;
логування.


requirements.txt
Містить Python-залежності, необхідні для запуску проєкту.
Якщо застосунок використовує лише стандартну бібліотеку Python, файл може бути порожнім або містити додаткові бібліотеки, якщо вони були використані.

Dockerfile
Містить інструкції для створення Docker-образу Python-бекенду.

compose.yml
Використовується для запуску всіх компонентів системи однією командою.
У проєкті Docker Compose використовується для запуску:
Python-бекенду;
Nginx.
nginx.conf

Конфігураційний файл Nginx.
Nginx використовується як reverse proxy та передає HTTP-запити до Python-бекенду.
images/
Директорія для збереження завантажених користувачем зображень.
Директорія підключається до контейнера як volume, тому завантажені файли зберігаються незалежно від життєвого циклу контейнера.

logs/
Директорія для збереження логів застосунку.
Основний файл логування:
logs/app.log

static/
Містить статичні файли застосунку, наприклад:
HTML;
CSS;


3. Функціональність
3.1. Головна сторінка
Для отримання головної сторінки використовується маршрут:
GET /
Маршрут повертає HTML-сторінку застосунку.
Залежно від параметрів URL може відображатися сторінка успішного завантаження або сторінка помилки.
http://localhost:8000/

3.2. Завантаження зображення
Для завантаження файлу використовується:
POST /upload
Файл передається у форматі multipart/form-data.
Перед збереженням виконуються перевірки.
Перевірка розміру
Максимальний допустимий розмір файлу:
5 000 000 байт
Якщо розмір файлу перевищує встановлений ліміт, завантаження відхиляється.
Користувач перенаправляється на сторінку помилки:
/?error=1

3.3. Перевірка формату
Дозволені формати зображень:
.jpg
.jpeg
.png
.gif

Якщо розширення файлу не входить до дозволеного списку, файл не зберігається.
У такому випадку користувач перенаправляється на:
/?error=1

3.4. Унікальне ім'я файлу
Для кожного завантаженого зображення генерується унікальне ім'я за допомогою UUID.
Наприклад:
a7c9f5e4c7e44e3e9c7c4e7a8f123456.jpg
Це дозволяє уникнути конфліктів, коли різні користувачі завантажують файли з однаковими назвами.
Оригінальна назва файлу не використовується як ім'я файлу на сервері.

3.5. Збереження файлу
Зображення зберігаються у директорії:
/images
Приклад:
images/
└── a7c9f5e4c7e44e3e9c7c4e7a8f123456.jpg

3.6. Посилання на завантажене зображення
Після успішного завантаження сервер генерує посилання на файл.
Наприклад:
http://localhost:8000/images/a7c9f5e4c7e44e3e9c7c4e7a8f123456.jpg

4. Ключові маршрути API
Метод	Маршрут	Призначення
GET	/	Відображення головної сторінки
POST	/upload	Завантаження зображення
GET	/images/<ім'я_файлу>	Отримання завантаженого зображення

GET /
Повертає головну HTML-сторінку.
Приклад запиту:
GET / HTTP/1.1
Host: localhost:8000
При успішному виконанні повертається:
HTTP/1.1 200 OK

POST /upload
Призначений для завантаження зображень.
При успішному завантаженні сервер повертає HTTP-редирект з переходом на сторінку з посилання на завантажене фото:
http://localhost:8000/images/<ім'я_файлу>

При помилці сервер повертає HTTP-редирект з переходом на сторінку помилки.

GET /images/<ім'я_файлу>
Використовується для отримання вже завантаженого зображення.
Наприклад:
GET http://localhost:8000/images/a7c9f5e4c7e44e3e9c7c4e7a8f123456.jpg
Якщо файл існує, сервер визначає його MIME-тип та повертає його вміст.
Якщо файл не знайдено:
404 Not Found

5. Логування
Для контролю роботи застосунку використовується логування.
Логи зберігаються у:
logs/app.log
Логуються як успішні, так і помилкові операції.
Приклад успішного запису:
2026-09-08 10:15:32 - INFO - Успіх: зображення photo.jpg завантажено. Розмір: 245678 байт.
Приклад помилки:
2026-09-08 10:16:04 - ERROR - Помилка: недопустиме розширення файлу exe.
Логи містять:
дату;
час;
рівень повідомлення;
опис дії;
додаткові деталі.

6. Обробка помилок
Сервер обробляє основні помилки під час роботи із запитами.
Приклади:
Файл занадто великий
Помилка: недопустимо великий розмір файлу!

Файл не вибрано
Помилка: файл не обрано!

Недопустиме розширення
Помилка: недопустиме розширення файлу.

Файл не знайдено
Сервер повертає:
404 Not Found

Внутрішня помилка сервера
У разі непередбаченої помилки повертається:
500 Internal Server Error
Помилка також записується до логів.

7. Локальний запуск без Docker
Перед запуском необхідно переконатися, що встановлено Python 3.
Перейти до директорії проєкту:
cd project
Виконати:
docker-compose up --build

Перевірити запуск
Після успішного запуску необхідно перевірити доступність застосунку.
Бекенд через налаштований Nginx доступний за адресою:
http://localhost:8000
Відкривши цю адресу у браузері, користувач повинен побачити головну сторінку застосунку.

9. Доступ до завантажених зображень
Завантажені файли зберігаються у директорії:
images/
Через Nginx вони доступні за адресою:
http://localhost:8000/images/<ім'я_файлу>

Таким чином, Python відповідає за обробку завантаження, а Nginx може використовуватися для роздачі 
статичних файлів.
